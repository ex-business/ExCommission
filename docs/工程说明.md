## 系统关系

当前由五个独立工程协作，运营身份与会员身份分开管理，代理后台与运营中心不融合页面。

| 工程 | 主要负责 | 当前本地入口 | 数据和权限边界 |
|---|---|---|---|
| ExCommission | 佣金规则、代理关系、奖励、结算、审批、报表 | API `127.0.0.1:19286`；worker `19287` | 业务库、资金事务、幂等及业务授权 |
| ExCommission-Web | 代理后台和会员代理页面；同源 BFF | [19486](http://localhost:19486/) | 浏览器会话与转发；不直接决定资金结果 |
| ex-ops-identity | 运营账号认证、站点角色、会话及审计 | 身份 API `127.0.0.1:19587` | 独立运营库；不复用会员账号 |
| ex-ops-identity-web | 运营人员账号、角色和站点管理页面 | [19586](http://127.0.0.1:19586/) | 只转发运营管理白名单；不承载代理页面 |
| ex-member-sandbox | 模拟会员注册登录、邀请及可靠事件投递 | [19386](http://127.0.0.1:19386/)；身份 `19387` | 独立会员库；不是正式会员平台 |

本地目录 `ex-member-sandbox-identity` 对应远程仓库 `ex-business/ex-member-sandbox`，不是额外的第六个工程。以上端口是本次联调实例，不覆盖各工程示例配置的默认端口。

```text
Ops browser -> Ops Web :19586 -> Ops Identity :19587 -> Ops DB
                                      ^
                                      | verify account / site / roles
Admin browser -> Business Web :19486 --+--> ExCommission :19286 -> Business DB
Member browser -> Business Web :19486 -> Member Identity :19387 -> Member DB
                                             ^
Member registration :19386 -> signed outbox --+--> ExCommission
ExCommission worker :19287 -> calculation / settlement / delivery
```

运营身份服务只提供账号、站点和角色；每个业务系统自行映射业务权限。其他尚未接入的业务系统不能因此视为已自动接通。

## 身份和权限

`internal/identity/adapters/ops.go` 使用固定的身份接口及本站映射。通用身份响应中的外部自报权限、租户和应用不会成为业务授权依据。

| 角色 | 本工程能力 | 保留边界 |
|---|---|---|
| viewer | 查看业务数据、方案、报表等 | 不写入、不付款、不审批 |
| applicant | 原申请人业务能力：条件编辑、试算发布申请、结算付款对账、导出、风控及修正申请 | 不能据此获得审批角色专属能力 |
| approver | 原独立审批能力、业务读取和审批恢复 | 不拥有方案编辑或付款写入权限 |

角色可组合，但同一主体仍不能审批自己的申请。全局运营管理员并不自动获得业务角色。原始认证作用域参与后续校验，复制 Principal 并改写站点不能扩大授权。

会员本人接口依赖会员身份；运营账号管理位于19586。签名事实、水位和渠道回调有独立接入约束。

## 配置与运行

Go 1.26.5；业务数据库为 MySQL。依赖及完整启动以根 README 和对应本地配置为准，不在文档中保存真实密码。

| 配置 | 用途 |
|---|---|
| `OPS_IDENTITY_CONFIG_FILE` | 权限0600的运营身份接入文件 |
| `endpoint` | 当前使用 `http://127.0.0.1:19587/internal/identity/introspect` |
| `secret` | 服务端接入密钥，不返回浏览器 |
| `sites` | 本系统固定的 site_id 到 tenant_id/app_id 映射 |

```sh
mkdir -p .local
go build -o .local/api ./cmd/api
go build -o .local/worker ./cmd/worker
```

先加载本机私有运行配置，再启动 API 和 worker。不要把此联调私有配置复制到 Git。身份配置缺省时保留旧本地身份兼容，但当前运营入口使用个人运营账号。

## 流程与异常处理

```text
Edit draft -> Simulate -> Submit request -> Independent review -> Scheduled activation
Signed facts -> Deduplicate -> Calculate -> Settle -> Review -> Claim -> Wallet receipt
```

更新必须携带对应版本/修订及幂等键。本人审批拒绝，旧版本冲突须重新读取；结果未知先查询原请求，不创建第二笔付款。奖励状态和钱包回执分开判断，领取接口成功与实际到账以原回执及查询结果核验。
