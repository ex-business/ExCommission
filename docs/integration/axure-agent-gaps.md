## 项目与模块边界

这是三个仓库的业务闭环；`ExCommission-dayend-commission` 是后端 worktree，不是第四个项目。当前实施文档分支为 `codex/affiliate-closure-plan`，隔离 worktree 为 `ExCommission-affiliate-closure`。后续代码在各仓库独立功能分支/worktree 开发，不修改其他会话目录。

|项目与基线|承担职责|扩展方式|
|---|---|---|
|ExCommission / master d987145|规则、事实、资格、奖励、账簿、审批、查询|复用 affiliate 领域计算与已审批配置；在独立 application/ports/adapters 中补编排、持久化和来源适配，不复制第二套计算公式|
|ExCommission-Web / 9dac8d3|后台配置和专用列表、会员 PC/H5|按 affiliate、agents、finance、member 页面模块接真实接口；计算器调用相同业务口径，不能以客户端算钱作为到账依据|
|ex-member-sandbox / master 147ed41|临时真实注册、会员身份和事实来源演示|扩展来源 outbox、日结水位和可信身份适配；会员不能自报充值/有效业务量作为生产事实|

后端扩展职责按下表拆分。表中是设计职责，不是声称已有这些 API 或数据表。

|扩展职责|输入与依赖|输出与边界|
|---|---|---|
|来源事实接入|来源签名、站点、订单号、成功/结算状态、业务时间、货币、场馆类型|不可变事实、幂等结果、日结水位；重复同号异内容拒绝，关账后迟到单进入调整|
|三套资格投影|发布配置版本、邀请关系、成功充值与已结算业务事实|等级/推荐/受邀分别累计，分别记录首次同时达标时间；不复用一个有效标志冒充三套资格|
|奖励权益|推荐逐档进度、受邀本人资格、审核通过的日佣金|持久化三类奖励，保留业务归属和配置版本；受邀本人/每推荐阶梯有唯一约束，重放不重复解锁|
|代理奖励开关|独立权限、TOTP、操作原因、开关版本|独立的可用区间；三类产出及领取统一检查，重开不补算关闭区间，不改变祖先链或压缩层级|
|日结编排|各受信来源水位、业务日期、站点时区、发布配置|可恢复任务：最终定级、计佣、日结、待审核；分阶段记录结果，失败可重试，不重复记账|
|领取编排|可信会员身份、领取类别、幂等键、可信请求上下文|锁定并记录本次领取的奖励集合；推荐/佣金各自一键领取全部待领，受邀独立领取；每笔权益保留独立账变|
|业务查询投影|事实、资格、权益、审核和领取事件|代理日表、贡献明细、三类记录及导出；按站点权限过滤，统一查询条件与汇总口径|

调用方向：页面调用业务接口；业务编排依赖领域规则及端口；MySQL、事实来源、钱包和身份提供方实现端口。领域代码不依赖 HTTP、页面或临时会员项目。临时来源以后替换为实际注册、充值和场馆服务，规则与奖励模块不重写。

                                                      |

<a id="compatibility"></a>
## 配置和历史兼容

业务固定规则与可配置运营参数分开。可配置阈值、奖励金额、阶梯新增人数、等级及费率、参与场馆、时区、人数统计周期；保留配置审批、历史版本和生效时间。周期、时区等已有不可变约束不因页面可编辑而放开。后台和会员端读取同一发布版本，不能各维护一份配置。

历史 referral 使用累计阈值，原型使用逐档新增人数。新增明确规则版本和切换时点；旧已解锁/已领取记录保留原始快照与唯一权益，不重新发放，不将旧版存量直接按新公式回放。新配置接入前须给出历史迁移预览与受影响人数/金额，不默认批准批量追补或改账。

IP/设备/共享账户去重采用独立风险策略端口，策略必须保存识别来源、去重范围、命中原因及版本。当前资料不足以唯一确定“同 IP/设备一个佣金”应按日、活动、受益人还是永久去重；不能随意选一个范围上线。只信任受控来源的识别结果；浏览器设备标识可被清除，不能当作不可伪造的设备身份。具体策略需依据原型细则确认后形成验收向量。

## 本轮登录与邀请接入进展

此节对应功能分支的工作区状态，不改变 master 完成判定。三个隔离工作区分别为 ExCommission-affiliate-closure（codex/affiliate-closure-plan）、ExCommission-Web-member-source（codex/member-source-login）、ex-member-sandbox-identity（codex/commission-identity-source）。

新增 memberaccess 端口与适配器，会员来源令牌通过独立内省验证，之后读取 registration 已提交回执获取内部 user_id。固定校验来源、站点、应用、签发方、受众、有效期；来源响应不能自带管理员权限。会员权限只初始化一次，后续登录不会恢复撤销授权。

服务端配置：

|项目|配置|作用|
|---|---|---|
|ExCommission|AUTH_MEMBER_SOURCE_FILE|私有 JSON：endpoint、client_id、client_secret、issuer、audience、source_id、local_sandbox；未配置保持旧登录|
|ExCommission|MEMBER_INVITATION_SOURCE=sandbox 且 LOCAL_REGISTRATION_ENABLED=true|使用注册邀请码适配器；注册地址取 LOCAL_REGISTRATION_URL；未启用保持旧会员链接路径|
|ExCommission-Web|MEMBER_SOURCE_FILE|私有 JSON：login_url、revoke_url、client_id、client_secret、local_sandbox；会员认证只用所配来源，不因失败回退同名旧账号|
|ex-member-sandbox|IdentityListen 等私有配置|独立身份端口，只监听回环；登录核验原有 PBKDF2 密码，来源令牌保存摘要，支持过期与撤销|

会员中心已有 referral-link 接口注入 RegistrationLinks 适配器，注册服务和会员页面共用 registration_invitations；账户行锁保证多幂等键并发请求仍复用同一码，数据库唯一约束及有限重试处理随机碰撞。新增分享码九位数字，旧邀请码继续可用于原始注册归属。原 member_referral_links 表和未启用站点的流程不被覆盖。

本地隔离运行：模拟会员页 http://127.0.0.1:18286/ ，会员中心 http://127.0.0.1:18186/?role=member ，后端18086，身份接入18287。使用原模拟会员数据库的一致性备份，原18280/18180/18082等进程未替换；新验收会员只加入副本及相同演示作用域的可信注册记录。此接入提供同账号登录，不是跨页面免登录。

已验证：后端 `go test -race ./...`（真实 MySQL）、模拟项目竞态测试、Web19项测试及构建；新增测试包含未同步拒绝、跨站/撤销拒绝、不恢复已撤销授权、并发稳定九位码。真实 HTTP 完成“模拟会员登录、会员中心分享、受邀注册、直属确认、新会员本人登录”；真实浏览器确认PC与390px H5会员中心，无页面异常及横向溢出。证据位于各隔离目录的 .local，只记录结论，接入密钥不进入仓库。
