# 每日自动结算与待审核记录

时间合同：沿用已实现的UTC每日业务日历。结算日D的到期时间为D+1日01:00 UTC；与电脑所在时区无关，不新增未支持的时区或夏令时日历。worker每5秒检查一次，到期后的下一次成功检查执行，不承诺硬实时秒级SLO。

首次启用把游标初始化为当时UTC日期的前一天；01:00前只登记，不提前生成。01:00后首次启动立即在检查时处理。游标保存MySQL，重启不重置；离线跨日按日期顺序、每次一日补齐，失败不推进游标。首次注册单独持久化，因此首次执行失败也不会在次日重置起点。首次启用不自动扫描更早历史，历史补单仍走既有接口。

到期时在同一事务中锁定租户/应用结算范围与调度游标，调用与手动相同的结算生成及提交逻辑，为每张新草稿生成STATEMENT待审核记录，申请人为system-settlement。生成结算、权益占用、待审核记录、执行审计与游标推进要么全部成功，要么全部回滚。多worker并发、同一时刻重复执行和重启不会重复生成本期结算或审核。

待审核不等于已经结算入可付款余额。人工审批仍重新校验金额、修订和冻结状态，禁止自动批准、自动付款。没有可结算佣金也保存空周期，不伪造零金额审核。冻结、reserved、最低付款额、迟到事实均遵循原有结算规则。

手动已生成的同周期全量结算会复用：草稿且从未申请审核才由系统提交；已经待审、批准或有历史审核的单据不再自动提交。同一张已驳回或撤回的结算单不自动重提；后续新周期仍按原有规则收录未结清权益并生成新的审核，不覆盖原审核结果。不同筛选范围的同周期手工运行、过时单据等冲突明确失败，保留原记录与游标，不覆盖历史或伪装完成；可通过下述调度状态及日志定位，须先处理冲突。手工提前生成更晚周期会被既有周期单调性约束拒绝回填，不静默跳过缺期。

按结算期生效的已注册UTC日历版本选版。没有有效日历时失败并保留游标；新版日历不重算历史。调度只处理worker明确配置的LOCAL_TENANT/LOCAL_APP（默认local-sandbox/commission），不会扫描或混合其他租户。

GET /v1/settlement-schedule（statements:read）返回 timezone=UTC、hour=1、poll_interval_seconds=5、initialized、next_period、next_due_at、last_result。尚未初始化的游标字段为null。last_result包含period、run_id、statement_ids、approval_ids与completed_at；它表示成功生成/复用结算与审核，不表示付款成功。

验证：00:59:59不执行、01:00执行、UTC日期边界、跨年、跨时区传入时钟、并发重复、重启追赶、空周期、人工单复用/审核拒绝不重提、签审独立、故障回滚及作用域隔离。数据库追加迁移，不改旧迁移摘要。Docker运行验收单独报告，不用单元通过代替已部署。
