## 演示前检查

1. 打开所需的同一组页面，确认页面可用；六个常用入口和三个验收入口本次检查均返回200。
2. 确认代理后台当前站点1000。多标签页切站后先刷新，旧表单被拒绝时不要重复提交。
3. 在会员中心确认已发布方案的币种、条件和费率。本次验收基线是USD、2位精度、UTC业务日、充值/有效投注门槛各1.00 USD、一级佣金比例0.4000%。
4. API与独立执行器都须启用`AFFILIATE_CLAIM_WALLET=wallet-sandbox`，共用同一`WALLET_SANDBOX_CONFIG_FILE`。单独改其中一方不能算接入完成。
5. 准备两个新会员和两个运营角色。已经关账的验收租户用于展示结果，重新从注册开始应创建新租户，不能把已撤单记录当成新案例重复提交。

当前API和执行器已启用独立钱包。服务端凭据只保存在私有配置中，浏览器不填写接入密钥、租户令牌或钱包签名。

## 完整流程与预期结果

```text
Register -> Invite -> Bind -> Deposit/Bet -> Qualify
                                            |
                                            v
Daily worker -> Independent review -> Claim accepted
                                            |
                                            v
Wallet credit -> Receipt -> Cancel original bet
                                            |
                                            v
Recovery debt -> Reconcile original order
```

| 步骤 | 页面操作 | 应看到的结果 |
| --- | --- | --- |
| 1. 推荐人注册 | 会员沙箱注册新推荐人，等待同步，生成邀请链接 | 代理身份已建立，生成专属邀请码 |

| 5. 自动日结 | 等来源完成业务日水位和次日调度；后台“结算与审核→代理日结/任务运行管理”查看 | 佣金0.40 USD，待审核，不可提前领取 |
| 6. 独立审核 | ops.applicant查看；退出后ops.approver登录，“代理业务奖励→每日佣金”，选择业务日，打开详情 | 一级贡献100.00 USD、费率0.4000%、佣金0.40 USD；填写备注、勾选核对、通过审核 |
| 7. 会员领取 | 推荐人登录佣金会员中心，只点击“每日佣金”的领取按钮 | 先显示领取已受理；钱包确认后已领取收益增加0.40 USD，不把推荐奖励一起领走 |
| 8. 钱包确认 | 运营账号登录对应钱包，查看入账订单、资金流水、回执任务 | 同一商户原单成功，金额40最小单位；流水1条，回执已送达 |
| 9. 原投注撤单 | 受邀会员在来源模拟选择投注撤单，使用新的撤单业务号，关联原投注业务号，撤销有效投注100.00并填写原因 | 撤单自动投递；不能新造无关负金额事件代替冲正 |
| 10. 查看追偿 | 后台“退款与调整→代理冲正记录” | 该佣金原应付40变0，新增追偿40；原已付流水保留，钱包不自动扣回 |
| 11. 原单追踪 | 后台“代理业务奖励→代理领取派发记录” | 领取、奖励、派发、会员、回执、回调和请求编号可关联查询；默认20条，支持20/50/100 |

金额栏标注“最小单位”时，USD的40表示0.40 USD，不是40美元。不同币种不能统一按两位小数换算。

## 异常与恢复

| 现象 | 先检查 | 安全处理与边界 |
| --- | --- | --- |
| 注册后等待同步 | 会员沙箱接入状态、来源日志和代理服务就绪 | 先刷新和等待自动重试；会员数据已保存时不要再注册同一账号 |
| 来源事件等待投递 | 事件编号、业务单号、尝试次数、结果码 | 网络故障自动重试；需人工补发时填写原因，用“按原事实补发”，不修改原事实或换单号重复报送 |
| 来源业务被拒绝 | 站点、来源权限、方案状态、币种及原单关联 | 修复明确原因后按原事实补发；已关账日期不能靠伪造水位或改时间重新写入 |
| 日结等待或水位缺失 | 任务运行管理的缺失来源、失败原因及代理日结状态 | 等来源补齐；任务重试须使用原任务的安全重试。停止方案不能借重试新增结算 |
| 待审核无法领取 | 业务日、金额、审核角色 | 由独立ops.approver核对后批准，不用申请人冒充审批人 |
| 领取已受理/结果未知 | 派发记录PENDING或UNKNOWN、钱包原单、API/执行器配置 | 等后台查询同一原单；不能换幂等键或手工再派发，更不能向内部钱包补记同一笔 |
| 钱包明确最终失败 | 派发状态FAILED_FINAL及失败原因 | 修复原因后显式重新领取；原失败单保留，不能删除历史记录来“重试” |
| 回执等待或被拒 | 钱包回执任务、客户端/站点绑定、签名密钥和目标地址 | 待发送任务会自动重试。被拒记录先核对原单归属；不能直接改成已送达或领取成功。历史无对应佣金原单的回执应拒绝 |
| 对账存在差异 | 原单、金额、终态、钱包回执及已付账本 | 保留差异供复核，不自动补款或扣款；对账不替代资金确认 |
| 对账待确认 | 钱包已有结果，但代理原单仍处理中 | 恢复派发原单查询/回执链路，再重新核对；只读对账不会提前释放或确认资金 |
| 对账无代理账单 | 选定的入账日期及是否属于当前站点/租户 | 不把0条理解成已核对全部资金；检查正确日期和入口 |
| 对账NOT_FOUND | 是否混入其他租户、旧手工模拟单或未知原单 | 未知原单仍应失败；不能将其强行归入当前代理。正常代理领取原单分流已修复 |
| 撤单后仍有钱包余额 | 冲正状态、原已付及追偿金额 | 本次是已领追偿，余额40分仍在；未经另行流程不会自动扣钱包，不重复冲正凑余额 |
| 页面403或会话站点变化 | 是否使用127.0.0.1、正确入口和当前站点 | 刷新并重新登录。保留Host/Origin、CSRF、站点绑定及入口验签，不用放宽校验解决访问问题 |
