# 代理任务运行管理

代理后台「结算与审核 → 任务运行管理」用于查看原方案和独立方案的日结依赖、执行阶段与历史，排队安全重试，并审批告警策略。

![任务运行与日结结果](images/affiliate-task-runs.png)

## 日常操作

1. 按状态或方案编号查询最近200个任务；`legacy` 表示原有代理方案。
2. 点击「详情」查看业务日、方案版本、缺失来源及其业务日、真实处理人数、错误原因和最近100次尝试。
3. 来源水位缺失时，由来源补齐对应业务日的事实与水位；重试按钮不能代替水位。人工检查也记录申请人、原因和追踪编号。
4. 失败时检查原因。业务申请人可填写原因后申请安全重试，worker 按原任务重新检查；已完成、执行中或已停止方案不能强制重跑。
5. 「告警与重试配置」由业务申请人提交，另一位审批人复核后生效。只读人员可查询；审批人员不能借此提交重试或修改配置。

日期按方案时区划分；页面所有执行时间明确标注 UTC。任务完成只表示日结事务已落库，待审核佣金仍须走原审核、领取或派发流程。

## 状态与处理

| 状态 | 含义与下一步 |
| --- | --- |
| 等待日结时间 | 业务日未结束，或未到原方案日结时间；无需重试 |
| 等待来源水位 | 展示真实来源编号和缺失业务日，跨时区可能涉及相邻日期 |
| 执行中 | 显示冻结、计算或生成待审核单等阶段；进度并非已到账金额 |
| 执行失败 | 保留错误与重试依据，按已生效策略退避重试，或申请人工重试 |
| 已完成 | 原日结结果已确认，不重复结算 |
| 已阻止 | 方案未启动、已停止、旧运行区间或站点暂停；保留历史 |

```
方案 / 版本 / 业务日
        |
        v
运行状态与来源水位检查 ----> 等待 / 已阻止
        |
        v
租约 + 原业务锁 + 原日结幂等键
        |
        +--> 失败留痕 --> 退避 / 人工排队 --> 重新检查
        |
        v
核对已提交日结结果 --> 已完成 --> 原审核与领取流程
```

停止后的旧权益继续按原流程结清；停止前尚未结算的日期不会因重试或重新启动而被自动补结算。

## 告警与自动重试

| 配置 | 默认 | 范围与作用 |
| --- | --- | --- |
| 站内告警 | 开启 | 保存触发、解除事件；不发送短信、邮件或外部消息 |
| 水位等待 | 30分钟 | 1～10080分钟，从进入等待状态计算 |
| 连续失败 | 3次 | 1～100次；缺水位检查不计作业务失败 |
| 日结超期 | 60分钟 | 1～43200分钟，从预计日结时间计算；已完成或已阻止不触发 |
| 失败自动重试 | 开启 | 仍复用原业务锁、状态校验和资金幂等键 |
| 自动执行上限 | 5次 | 1～100次，按任务累计；人工检查不消耗自动预算 |
| 基础 / 最大间隔 | 30 / 900秒 | 基础5～3600秒，最大不小于基础且不超过86400秒 |

同一任务同类告警只触发一次；条件解除或规则停用会保存解除事件。页面是事件历史，旧触发事件不会被删除；可点击任务编号查看详情。修改规则不重算佣金。

## 接口与实现

| 接口 | 权限 / 用途 |
| --- | --- |
| `GET /v1/affiliate/task-runs` | `tasks:read`，当前认证站点列表，支持 `status`、`program_id` |
| `GET /v1/affiliate/task-runs/{id}` | `tasks:read`，原任务和最近100次历史 |
| `POST /v1/affiliate/task-runs/{id}/retry-requests` | `tasks:recover`，仅提交 `reason`；需 `Idempotency-Key`，202表示排队 |
| `GET /v1/affiliate/task-alerts` | `tasks:read`，规则及最近300条告警事件 |
| `POST /v1/affiliate/task-alert-config-requests` | `affiliate:configure`，提交 `expected_revision`、`rules`、`reason`；需幂等键，返回审批编号 |

告警审批类型 `AFFILIATE_TASK_ALERT` 使用 `affiliate:approve`，沿用本人不能审批和版本冲突校验。浏览器不能传入站点、修改原任务日期、方案版本或资金幂等键，租约令牌不返回浏览器。

核心模块为 `internal/affiliatetasks`，表结构为迁移 `034_affiliate_tasks.sql`。运行记录独立提交，业务事务回滚后仍可查失败；原日结提交后发生连接中断时，以真实日结结果为准。两分钟租约带令牌围栏，过期恢复保留原申请人，旧执行器不能覆盖新结果。最终资金防重仍由原业务事务锁和幂等键保障。

worker 沿用原每5秒检查、单轮20秒超时和配置的站点作用域；多站部署需为相应作用域运行 worker。本次未增加跨站自动扫描或外部通知服务。列表优先显示最近200条；发现当前日、最近应结日、原始事实业务日及已有待处理日，不补造没有事实的全部历史空白日。

## 验证与影响

- 真实 MySQL + `-race`：等待依赖、告警去重与解除、独立审批、自审拒绝、只读拒写、跨作用域不可读、退避与自动预算、人工恢复、并发租约、取消后留痕、过期租约及旧令牌围栏通过。
- 实际独立方案生命周期验证：无水位可见、停止阻止、补齐后只结算一次、重启不补结旧区间。
- 原会员资格 / 领取、六类冲正与追偿回归通过；`go test ./...`、`go vet ./...` 通过，契约18项通过。
- 前端构建与27项测试通过；浏览器验证只读入口、重试排队、配置审批跳转。隔离 API / worker 通过签名水位触发原方案和独立方案的空业务日日结与告警解除；含会员事实和资金结果由 MySQL 集成测试覆盖。

【涉及其他业务】代理日结调度、来源水位等待、共用审批类型分发新增任务跟踪与告警审批；原日结事务继续校验运行状态，领取和冲正沿用原规则。其他 worker 作业、公共登录、BFF鉴权和付款规则未在本次任务管理中修改。未做真实外部来源、真实钱包或生产负载验收。
