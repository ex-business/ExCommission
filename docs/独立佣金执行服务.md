# 独立佣金执行服务

`ex-commission-executor` 是独立工程和部署产物，固定调用本工程新增的 `worker.Run()`；运行原后台任务，不注册业务API路由。

```
ExCommission API --> 共享业务数据库 <-- ex-commission-executor
配置 / 审批 / 查询                       计佣 / 日结 / 恢复
```

业务规则仍在本工程维护；新工程不复制计算器、账务、租约、状态流转或付款规则。`internal/runtime/server.go` 与旧 `cmd/worker` 未修改，旧部署可继续使用。

共享模块新增公共入口在 `worker/worker.go`，作用固定为worker。进程继续使用原数据库迁移、健康检查、环境配置、单作用域调度和退出逻辑。API业务账号、站点授权及审批入口仍由原系统管理，后台执行审计身份仍为 `system-worker`。

独立入口随本次主线发布；独立工程锁定包含入口的具体提交版本。可使用固定远程模块构建，也可在本地引用经快照校验的同一源码，不使用动态main依赖。

完整系统关系见 [系统架构与调用关系](系统架构与调用关系.md)。

验证：新旧执行进程同时处理真实签名模拟事实和来源水位，日结及佣金没有重复；停止方案拒绝新结算；API停止后新进程继续就绪；重启保留原日结及佣金编号；新端口不提供业务API；非root只读容器通过就绪检查。

【涉及其他业务】原计佣、代理日结、派发/退款恢复、对账等后台作业的进程承载变化；规则实现未修改。回退只切回旧worker入口，不删任务或资金数据。真实外部钱包、生产负载和跨站规模部署未验证。
